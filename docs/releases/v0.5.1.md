# mockryx v0.5.1

A patch release on v0.5.0. Five shipped drills could report a false `Finding` on a healthy stack because they waited for heraldyx in a later step than the request heraldyx reacts to; they now wait in that step. The build moves to Go 1.27.4 for GO-2026-6859. No exit status, `Finding` semantics, scenario format or setting changes, and no scenario capability is added.

## Fixed

- **The reaction chain waits for heraldyx in one step (#96).** In v0.5.0 `reaction-chain-reaches-heraldyx` sent the same denied request twice: step 1 waited for `wardryx`/`policy_deny`, step 2 for `heraldyx`/`alert_sent`. mockryx counts a reaction only from the second in which the waiting step's own request went out (invariant 11, the floor), and heraldyx writes one `alert_sent` per run, about step 1's denial. Whenever heraldyx journalled it before step 2's request went out, step 2 refused it as too early: a false `Finding`. The drill is now one step, `shell-exec-denied-and-heraldyx-notifies`: the denied request, `403` + `x-fuse-wardryx: deny`, and `heraldyx`/`alert_sent` within 30s. The floor did not move, and the README's "Async reaction checks" now tells a scenario author to wait for a reaction in the step that sends the request it reacts to.
- **The game-day drills wait for heraldyx in their first step (#97).** `game-day/provider-5xx`, `provider-rate-limited`, `provider-timeout` and `provider-outage` sent the same failing call twice and waited for heraldyx's alert in the second step, the same shape as above. The two steps swapped places: step 1 now waits for `heraldyx`/`alert_sent`, and step 2 sends the same call and checks the gateway's answer, in the three provider drills together with the gateway's own `tokenfuse`/`dependency_failed`, which the gateway writes for every failed call. The steps keep their names and their checks; only the order changed.

## Added

- **`reaction-chain-reaches-wardryx` (#96).** Wardryx's own off-path record of the denial, which the old heraldyx drill checked in its first step, has a drill of its own: the same request, `403` + `x-fuse-wardryx: deny`, and `wardryx`/`policy_deny` within 10s, `requires: wardryx`. A missing Wardryx record fails both drills; a silent heraldyx fails the heraldyx drill alone, so a `Finding` still names the link that broke.

## Security

- **Go 1.27.4 (#95).** GO-2026-6859, an HTTP/1 server crash in `net/http` from a `MaxBytesReader` header race, is present in go1.27.3 and fixed in go1.27.4. The binaries and the image of this release are built with go1.27.4. The release workflow's actions were also bumped (#92): cosign-installer v4.1.3, docker/login-action v4.8.0.

## Upgrade

Pull `ghcr.io/taipanbox/mockryx:v0.5.1` in place of `v0.5.0`, or download the binary for your platform from this release. No setting, stored state or wire format changes, so there is nothing to migrate. To roll back, run v0.5.0 again.

A run over the whole scenario directory now runs one more drill, `reaction-chain-reaches-wardryx`, which reads the same Wardryx stream `reaction-chain-reaches-heraldyx` already needed. A deployment that runs `reaction-chain-reaches-heraldyx.yaml` on its own keeps the heraldyx check and loses the Wardryx one; add `reaction-chain-reaches-wardryx.yaml` to keep both. A deployment that replaces a shipped scenario with a copy of its own, by a mount over the file, should compare its copy with the new file before it moves to this image.

## Evidence

- `features/reaction-chain.feature` and `features/provider-failure-game-day.feature` carry the new scenarios, each bound to a test (`scripts/features-are-bound.sh`).
- Each regression test was run against v0.5.0's scenarios first and went red with the false `Finding` itself: "1 matching line(s) seen but refused on time". The model behind them answers at second precision and keeps heraldyx's one alert per run, as the real planes do, and is read back by the real `internal/watch`.
- Planted faults, each caught: for the reaction chain, the heraldyx drill waiting for Wardryx, the Wardryx drill expecting `200`, the Wardryx drill waiting for heraldyx and a pinned `run_id`; for the game-day drills, the old step order, a pinned `run_id` and heraldyx waited for in both steps.
- `VALIDATION.md` records both: "The reaction chain in one step, and Verdryx's `quality_drift`" and "The game-day drills wait for heraldyx in their first step", both 2026-11-12.
- 269 test functions (262 in v0.5.0); `scripts/gates-have-teeth.sh` runs 54 cases (53).
